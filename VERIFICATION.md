# Проверка 11.11.2026

## Автоматические проверки

`npm test`: 9 из 9 сценариев прошли, ошибок и пропусков нет. Использованы встроенный `node:test`, общий серверный обработчик и настоящая SQLite. Отдельный тест запускает локальный HTTP-сервер, отправляет именной и анонимный ответ, останавливает процесс и запускает новый с тем же файлом базы.

1. Главное: график в именном обращении → действие HR → исправление → подтверждение → сохранённый план найма.
2. «Не помогло» возвращает статус в работу; устаревшая версия обращения даёт 409.
3. Анонимный API принимает только answers/comment, отвергает employee_id/session_id/fingerprint; схема без связи с сотрудником, история не пополняется, расписание не меняется. У сообщения нет поля подтверждения и точного времени, случайный ID записи не возвращается автору. Проверена работа анонимной отправки даже при отсутствии сотрудников в БД. Для закрытия нужна собственная проверка HR.
4. Пустые, неверные и неполные ответы отклоняются. Текст необязателен. Проверены пустое действие, ответственный и неверная календарная дата.
5. Увольнение сохраняет обращение и изменение процесса, запрещает новое именное сообщение и подтверждение от уволенного. Для закрытия требуются план и проверка HR.
6. Первый опрос через два рабочих дня, интервалы 3/2 рабочих дня, пропуск выходных.
7. Межсайтовый POST с чужим Origin запрещён, JSON не кэшируется, неверный JSON и неизвестный маршрут обрабатываются.
8. Закрытие/открытие файла SQLite сохраняет данные, миграция не применяется повторно.
9. Реальный перезапуск серверного процесса сохраняет оба типа сообщений; в личной истории остаётся только именное.

`npm run build`: Worker собран; синтаксис браузерного JavaScript проверен через `vm.Script`. `node --check dist/server/index.js` прошёл.

## В браузере

Проверено в браузере внутри Codex через CUA, без настоящих данных:

- пустой опрос не отправляется; браузер предлагает выбрать вариант;
- заполнение примера и именная отправка; срок следующего опроса меняется с 11 на 16 ноября;
- HR видит обещанный график, сохраняет ответственного, срок, действие и результат;
- статусы «В работе», «Ждём проверки», подтверждение «Да, помогло», затем «Решено»;
- изменение найма с ответственным и проверкой сохраняется во вкладке «Изменения» со статусом «Запланировано»;
- анонимная отправка на мобильном экране: успех, количество личных обращений остаётся 1; в HR отдельная карточка без имени и карточки сотрудника;
- ширины viewport 390×844 и 320×740: обе роли помещаются по ширине. Проверено через DOM scrollWidth; горизонтальная прокрутка разрешена внутри ленты обращений и навигации, а не всей страницы;
- обновление страницы сохраняет обращения и изменение процесса.

Скриншоты этапов сохранены локально в `outputs/`. Проверка веток «не помогло», увольнения и закрытия анонимного обращения выполнена автоматическими API-тестами, но отдельно через UI эти ветки не проходились.

## Найдено и исправлено

- Ошибка количества параметров при создании вымышленных сотрудников — исправлена, seed и тесты прошли.
- В мобильном HR лента карточек растягивала сетку, на 320 px этапы помощи растягивали страницу — исправлены ограничения сетки и раскладка этапов; ширина перепроверена.
- Повторная сборка на Windows упиралась в ошибку перезаписи через fs.cpSync — заменена на запись прочитанного манифеста, повторная сборка прошла.
- Подтверждение новичка защищено от сохранения нового результата под старым подтверждением: для изменения исправления HR должен вернуть обращение в работу.

## Что эти результаты не доказывают

Здесь перечислены локальные проверки. Результат облачной публикации, фактический доступ по ссылке и проверки D1 фиксируются отдельно при сдаче. Локальная SQLite не доказывает успешность облачных миграций.

Не выполнены: нагрузочное тестирование, аудит хостинговых/сетевых журналов и невозможности идентификации по ним, проверка на физических телефонах и Safari, полноценный аудит безопасности/доступности, восстановление из резервной копии, интеграция с Битрикс24. Не было пилота с людьми, и нет измеренного влияния на увольнения. Оптимистическая блокировка действует для действий HR и подтверждений; редактирование плана процесса пока использует последнее сохранение. Идентификация ролей демонстрационная, сотрудники общие для всех посетителей.

HR не может закрывать именные обращения, включая обращения уволенных. Прежний тест увольнения обновлён под новое требование, старые записи выше — история предыдущих версий.

Локальный сервер остановлен перед отправкой: показана понятная ошибка, текст сохранён, кнопка доступна, ложного подтверждения нет. После запуска сервера повторная отправка прошла.
