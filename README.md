# Новичок

**[Открыть работающий сайт](https://novichok-help-demo.gali-hey.chatgpt.site/)**

Демонстрационное приложение для компании, HR и новичка: заметить трудность, назначить исправление, проверить его результат и сохранить изменение для следующих сотрудников.

Оригинал задания прочитан: https://docs.google.com/document/d/1rWuLv17nxG8FlThRgBysK_ghcMfhhv-bO403C34knZQ/edit

**Все данные вымышлены. Это демонстрация без разграничения прав. Не вводите настоящие данные сотрудников.** 

## Запуск за минуту

Нужен Node.js 24 или новее. Устанавливать пакеты не требуется: приложение использует только встроенные модули Node.

```sh
npm start
```

Откройте http://127.0.0.1:4173. Сервер слушает только локальный интерфейс. Если порт занят, задайте `PORT`. Для другого файла базы используйте `DEMO_DB` (каталог файла должен существовать). Например, в PowerShell:

```powershell
$env:PORT = '4180'
npm start
```

Остановка: Ctrl+C. Node может показать `ExperimentalWarning` для встроенного SQLite; это предупреждение выбранного runtime, приложение продолжает работать.

Данные сохраняются в `data/demo.sqlite` между перезапусками. Миграции применяются при запуске, вымышленные сотрудники создаются один раз при открытии сайта. После остановки сервера можно скопировать всю папку `data` для резервной копии. Перезапуск не сбрасывает обращения. Кнопка сброса в HR удаляет только данные этой общей демонстрации после явного подтверждения.

## Проверка и сборка

```sh
npm test
npm run build
```

Первое — автоматические сценарии через общий HTTP-обработчик и SQLite, включая запуск нового процесса сервера. Второе — проверка синтаксиса браузерного кода и сборка Worker в `dist/server/index.js`. Нет платных API, ключей, CDN, внешних шрифтов или сборочных зависимостей.

Для публикации Sites используется `.openai/hosting.json` с привязкой `DB` и SQL-миграции `drizzle/`. Облако хранит записи в D1. Локальная SQLite и облачная D1 — отдельные базы: локальные демонстрационные ответы в облако не копируются. Серверный обработчик общий для обоих вариантов. Публикация выполняется инструментами Sites из точного Git-коммита; `npm run build` сам по себе не публикует сайт и не применяет облачные миграции.

Адрес подготовленного сайта: https://novichok-help-demo.gali-hey.chatgpt.site. Фактический результат публикации и облачных проверок указан в материалах сдачи, а не выводится из наличия этого адреса в README. Пользователь разрешил публичный доступ 11.11.2026. Общая демонстрационная база доступна всем посетителям с переключением обеих ролей.

## Что работает

- Новичок Илья Макаров: три обязательных вопроса, необязательный текст до 2000 символов, выбор отправки с именем или без него.
- Первый опрос после двух рабочих дней. Затем интервалы 3 и 2 рабочих дня по календарю пн–пт. В инструкции написано «Пройдите первый опрос — спустя два рабочих дня после выхода на работу». Обе строки можно менять в редакторе. Расписание по-прежнему рассчитывается сервером, но на экране новичка дата вместо этой инструкции не показывается. Проходить опрос в демо можно без ожидания.
- HR видит ответы и именную карточку с обязанностями, графиком и оплатой. Фактическое расхождение описано самим новичком; приложение не объявляет его установленным фактом автоматически.
- Ответственный, срок, конкретное действие, описание исправления; статусы «Новое → В работе → Ждём проверки → Решено».
- На странице новичка два состояния: «Обращение принято» и «Ваш запрос решён». Под каждым открытым именным обращением есть кнопка «Проблема решена». Новичок может нажать её в любое время, без ожидания действий HR. HR не может закрыть именное обращение или отменить отметку новичка. Внутренние этапы работы HR сохранены только в его разделе.
- Отдельный план изменения процесса: что изменить, кто и когда сделает, как проверить, фактический результат проверки HR. Выполненным его можно отметить только с заполненным результатом.
- Увольнение отмечается в HR. Обращения и изменения сохраняются. Если новичок ушёл, HR сохраняет план для следующих новичков и свою проверку. Именное обращение без отметки новичка не объявляется решённым. Причина увольнения из обращения не выводится.
- У именных и анонимных обращений одна очередь HR. При увольнении и при анонимном сообщении не создаётся фиктивное подтверждение автора.

## Анонимный канал

Клиент отправляет `POST /api/anonymous` с JSON **только** из полей `answers` и `comment`. Нет идентификатора сотрудника, имени, подразделения, ссылки на карточку, client/session ID или отпечатка браузера. Используются `credentials: omit` и `referrerPolicy: no-referrer`. Приложение не создаёт cookies, localStorage, аналитику или журналы запросов. Предпочтения роли также не записываются.

Сервер отклоняет лишние поля. Запись попадает в `anonymous_reports`, где нет employee_id, внешнего ключа на сотрудников, поля подтверждения или точного времени. Сохраняется календарный день по Москве и случайный ID самого обращения. Этот ID не возвращается автору. Анонимная отправка не читает и не изменяет карточку сотрудника. Личная история запрашивает только `named_reports` текущего демо-сотрудника. Личное расписание не обновляется по анонимному ответу.

На экране перед отправкой объясняется: имя не передаётся HR, ответ не появится в личной истории, HR не сможет связаться с автором или запросить подтверждение. Текст не очищается автоматически от добровольно введённых имён. По деталям истории автора иногда можно узнать; не вводите личные данные.

Это проверка анонимности **на уровне приложения**, а не обещание невозможности идентификации вообще. Хостинг и сетевые операторы могут обрабатывать IP, технические журналы и данные доступа; аудит этих систем не выполнялся. Публичное демо не подходит для реальных HR-данных.

## Выбор задачи и границы

Каждый третий **из уволившихся**, а не каждый третий новичок, работал меньше трёх месяцев. Общее число увольнений и причины неизвестны. Поэтому выбран управляемый сценарий помощи, а не прогноз ухода. Не утверждаем, что исправление графика стало бы причиной сохранения человека в компании.

ИИ для этой версии не нужен: работа заключается в сборе ответов и выполнении договорённостей. Классификация текстов может стать следующим экспериментом только при явной пользе и с проверкой HR. Прогнозов увольнения, оценок сотрудников и декоративной аналитики нет.

Не реализованы Битрикс24, рассылки, голос, распознавание речи, настоящий вход и права доступа, календарь смен/праздников, защита от спама, неизменяемый журнал действий, резервирование и восстановление облачной БД. Текущий календарь пн–пт — явно обозначенное допущение для демо, не график всего склада или всех магазинов. Облачное демо — одна общая база; это не многопользовательская production-система.

Следующий шаг: согласовать маршрутизацию и ответственность HR, проверить календарь с компанией, сделать безопасную авторизацию и изолированный анонимный канал, затем провести небольшой пилот. Сначала измерять время до помощи, долю проверенных исправлений и повторение проблем. Влияние на увольнения проверять отдельно при наличии общего количества увольнений, численности новичков и подходящего сравнения.

## Файлы

- `src/index.html` — интерфейс, стили, браузерный код.
- `src/core.js` — серверная валидация, расписание, переходы и обработка обращений.
- `scripts/local.mjs`, `scripts/database.mjs` — локальный HTTP-сервер и адаптер SQLite.

- `DEMO.md` — сценарий показа до трёх минут.
- `REPORT.md` — проект отчёта работодателю до 15 строк; самостоятельно не отправлялся.
- `VERIFICATION.md` — проверенные сценарии, методы, обнаруженные ошибки и пределы проверки.

## Временное редактирование текстов

По явному запросу пользователя редактор временно работает без пароля. Редактор находится отдельно по адресу `/editor`. На обычной странице `/` кнопок редактора нет. При открытии `/editor` правки доступны сразу. После «Завершить» можно выбрать другую роль и снова нажать «Редактировать тексты». Нажмите на обведённый текст, измените его, нажмите «Сохранить», затем «Завершить». Для другой роли сначала завершите правку, переключите роль и снова откройте редактор. Сохранение явное, не автоматическое; при несохранённых правках браузер предупреждает перед выходом. Тексты хранятся в таблице site_copy в SQLite/D1, видны другим посетителям после обновления страницы и сохраняются при перезапуске. Сброс демонстрационных обращений тексты не удаляет.

Редактируются подписи, заголовки, пояснения, вопросы и текст кнопок. Данные сотрудников, ответы, содержимое обращений, даты и динамические статусы этим редактором не меняются. Одинаковые исходные подписи используют общий перевод. Редактор не меняет HTML, стили, плейсхолдеры полей или бизнес-логику вариантов ответа. Вставка и отображение — обычный текст. Эмодзи не допускаются.

Флаг runtime `ENABLE_TEXT_EDITING=true` включает редактор. Чтобы отключить его после правок, установить `ENABLE_TEXT_EDITING=false` и применить конфигурацию новым развёртыванием. Сервер запретит запись, кнопка исчезнет; сохранённые тексты останутся видны. Локальный запуск редактора в PowerShell: `$env:ENABLE_TEXT_EDITING='true'; npm start`. Без флага локально и на сервере редактор отключён по умолчанию. Паролей и ключей для него по текущему запросу не создавалось.

Иконки выполнены как SVG. Unicode-символы, способные стать эмодзи на мобильном устройстве, в качестве иконок не используются. Правило закреплено в AGENTS.md.

## Простая страница новичка

После именной или анонимной отправки появляется заметный блок «Ваш ответ принят». Именной ответ виден в личном списке, анонимный — только HR. При ошибке связи текст остаётся в форме, отправку можно повторить; прежнее подтверждение не выдаётся за успех новой попытки. В «Моих обращениях» две подписи и одна кнопка решения для новичка. Правило простого бытового языка для читателя 13–14 лет закреплено в AGENTS.md.

## Простой экран HR и быстрое переключение

HR видит один список обращений. Кнопки «Нужна помощь», «Решённые» и «Все обращения» меняют только список. Нажмите на карточку, чтобы открыть её. Внутри — полные вопросы и ответы, затем форма «Как поможем?»: что сделать, кто поможет и до какого дня. Поле «Что уже сделано?» можно заполнить позже. Кнопка «Сохранить помощь» сохраняет план без ручного выбора статуса. Именное обращение по-прежнему отмечает решённым только новичок. Для анонимного ответа HR сам записывает, что сделано и как проверено, и ставит отметку проверки; это не подтверждение автора.

«Что обещали при найме» открывает личные условия только именного обращения. «Чтобы это не повторилось» сохраняет отдельный план для следующих новичков. Если человек уволен, этот блок открыт сразу. Причина увольнения не выводится из обращения. Отдельные вкладки сотрудников и изменений убраны из интерфейса; соответствующие записи и планы в базе сохранены. Сброс спрятан в «Настройки демонстрации».

Роли переключаются до запроса к серверу. Уже полученные данные показываются сразу; свежие загружаются отдельно. При первом открытии ещё не загруженной роли сразу виден её экран с сообщением о загрузке. Черновики форм сохраняются в памяти вкладки при переходе между ролями, но не после перезагрузки. Явная кнопка обновления загружает свежие данные и сбрасывает черновики; не нажимайте её, если хотите сохранить несохранённый текст. Успешно отправленные ответы и помощь хранятся в базе.

В «Моих обращениях» ответы показаны под заголовком «Мои ответы на опрос»: полный вопрос и ответ, без сокращений «Задачи / Работа / Условия».
